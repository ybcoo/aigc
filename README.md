# AIGC Studio

An AI creation workspace built with Nuxt/Vue Flow, NestJS, Prisma and PostgreSQL.
Create a project from a script or TXT chapters, then work with connected text,
image, audio and video nodes on an infinite canvas. Background generation tasks
support cancellation, reference inspection and media history. The FFmpeg-based
video editor supports video/audio/subtitle tracks and MP4/MP3 exports.

The canvas workflow was adapted from localMiniDrama/aiedu-lab. This repository
focuses on the canvas experience rather than the original list view.

## Repository Layout

```text
.
|-- compose.yaml              # PostgreSQL, migrations, backend and frontend
|-- .env.example              # Docker settings, without real credentials
|-- aigc-backend/             # NestJS API, Prisma migrations and FFmpeg editor
`-- aigc-fronted/             # Nuxt app (directory spelling retained intentionally)
```

## Docker Quick Start

Requirements: Docker Engine/Desktop with the Compose plugin. Images use Node.js 24
and PostgreSQL 16. The backend image includes FFmpeg, libass and CJK fonts.

From this directory, on first setup:

```bash
cp .env.example .env
```

Edit `.env`, especially `POSTGRES_PASSWORD`. Use a random hex password, for example
one generated by `openssl rand -hex 24`. The password is interpolated into the
database URL; special characters require a URL-encoded `DATABASE_URL` override.
Do not overwrite an existing environment file when upgrading.

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps -a
```

- Frontend: <http://localhost:3000>
- API: <http://localhost:3001/api>
- PostgreSQL is internal to Docker; no host database port is published.
- Startup waits for database readiness, runs `prisma migrate deploy`, then starts
  the backend and frontend. An exited `migrate` container with code 0 is normal.
- Configure text/image/video providers in the app's AI settings. API keys are not
  build arguments and do not belong in frontend environment variables.

If ports are occupied, change `FRONTEND_PORT` / `BACKEND_PORT` and update
`FRONTEND_ORIGIN` / `NUXT_PUBLIC_API_BASE` to match. A browser-facing API URL must
not use the Docker hostname `backend`.

Compose uses the root `.env`, not either application's local `.env`. Application
environment files are excluded from Docker builds.

## Configuration

| Variable | Purpose |
| --- | --- |
| `HOST_BIND_IP` | Published interface; defaults to local-only `127.0.0.1`. |
| `FRONTEND_PORT`, `BACKEND_PORT` | Host ports, defaulting to 3000 and 3001. |
| `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD` | Database initialization and connection settings. |
| `DATABASE_URL` | Optional override; URL-encode credentials with special characters. |
| `NUXT_PUBLIC_API_BASE` | Browser-visible API URL ending in `/api`; configurable at container startup. |
| `FRONTEND_ORIGIN` | Comma-separated allowed frontend origins, including scheme and port. |
| `STORAGE_DRIVER` | `local` (default) or `oss` (Cloudflare R2). |
| `PUBLIC_ASSET_BASE_URL` | Public backend origin serving `/uploads` in local mode. |
| `R2_*` | Cloudflare R2 settings; required for `STORAGE_DRIVER=oss`. |

Changing initialization variables does not change PostgreSQL users/passwords in an
existing volume. Update database credentials deliberately instead of deleting data.
For an external database, set `DATABASE_URL`; the bundled `db` service remains
available but the backend and migration service use the override.

### Media Storage

`local` persists media in the `uploads` volume. AI providers need a publicly
reachable `PUBLIC_ASSET_BASE_URL` to fetch local video/audio references, for
example `https://api.example.com`. Remote providers cannot fetch `localhost`,
LAN-only addresses or Docker hostnames.

For R2, configure `STORAGE_DRIVER=oss`, bucket, credentials and public base URL.
Provide either `R2_ACCOUNT_ID` or `R2_ENDPOINT`. `R2_PUBLIC_BASE_URL` must serve
public objects; it is not the authenticated S3 API endpoint. Configure bucket
CORS for browser JavaScript media reads. Switching storage modes does not migrate
existing media. Keep the uploads volume even in OSS mode for editor working files
and existing local URLs. See [storage notes](aigc-backend/src/storage/README.md).

### Public Deployment

The app currently has no user authentication or project-level authorization.
Do not expose it directly to the Internet. Protect **both** frontend and backend,
including media routes, with an authenticated HTTPS reverse proxy or equivalent
access controls. CORS is not authentication.

Keep `HOST_BIND_IP=127.0.0.1` when the proxy runs on the same host. Set real domains:

```dotenv
NUXT_PUBLIC_API_BASE=https://api.example.com/api
FRONTEND_ORIGIN=https://studio.example.com
PUBLIC_ASSET_BASE_URL=https://api.example.com
```

Allow uploads up to 100 MB at the proxy. R2 or a separately public media origin
may be needed when AI providers cannot pass your authentication layer. Treat
database backups and generation task logs as private data. Use one backend replica:
task controllers are process-local, and startup marks interrupted tasks as failed.
Multiple replicas require a shared worker/queue design first.

## Local Development

Install Node.js 24, PostgreSQL 16 and FFmpeg/ffprobe. FFmpeg needs libx264, AAC,
libmp3lame, libass/subtitles, drawtext and xfade. Install fonts covering your subtitle
languages. Create the `aigc` database with your PostgreSQL administrator tool.

Backend, in one terminal, on first setup:

```bash
cd aigc-backend
cp .env.example .env
# Edit DATABASE_URL before running migrations.
npm ci
npm run prisma:generate
npm run db:migrate
npm run start:dev
```

Frontend, in another terminal:

```bash
cd aigc-fronted
cp .env.example .env
npm ci
npm run dev
```

Do not overwrite existing `.env` files or run local servers on ports used by Docker.
Prisma reads `DATABASE_URL`, not separate `DB_HOST` / `DB_USER` variables. Outside
Compose, starting the API does not automatically create/migrate the database.

## Maintenance

```bash
docker compose logs -f --tail=100 backend frontend
docker compose logs migrate
docker compose exec backend ./node_modules/.bin/prisma migrate status
docker compose down
```

`down` retains named volumes. Do not add `-v` unless you intend to permanently
delete the database and local media. Back up both; R2 objects are separate.
Database backups include private prompts and model configuration:

```bash
mkdir -p backups
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backups/aigc.sql
docker compose cp backend:/app/uploads backups/uploads
```

Wait for or cancel active tasks and take backups before upgrading:

```bash
docker compose build
docker compose stop frontend backend
docker compose run --rm migrate
docker compose up -d
```

If migration fails, leave the app stopped and fix the cause. Do not reset a populated
database to bypass migration errors. Environment changes require container
recreation with `docker compose up -d`, not just `docker compose restart`.

## Verification

```bash
cd aigc-backend
npm run build
npm run test:image-provider
npm run test:video-provider
npm run test:script-import

cd ../aigc-fronted
npm run build
npm run test:home
npm run test:canvas
npm run test:editor
```

Backend integration tests require a migrated **test** database. Never point them
at production. They create temporary project fixtures and use fake AI providers.

## Before Publishing to GitHub

- Commit source, lockfiles, Dockerfiles, migration history and sanitized examples.
  Do not commit `.env`, uploads, backups or build output.
- Inspect the staged diff for credentials. Ignore rules do not remove files already
  tracked; rotate any credential previously published.
- If there are nested `.git` directories, choose one repository or separate
  repositories/submodules before staging. Adding an embedded repository does not
  automatically add its source files. This setup does not change Git metadata.
- Retain upstream notices and [featured media credits](aigc-fronted/public/featured/README.md).
  No project-wide open-source license is selected here. Review upstream and asset
  terms before choosing one; do not infer a license from the NestJS starter.
